# SwapVM v1.1 authentication migration report

## Outcome

SwapVM v1.1 closes the v1.0 actor-reclassification flaw before Stage 6 begins. Every authenticated root action now carries an explicit signed EVM `actor`; the Kernel rejects a zero actor and requires the recovered ECDSA signer to equal that actor before it reads or advances nonce state.

The correction changes only the outer authenticated action boundary:

- `address actor` is inserted after `worldId` in `VMEnvelope` and the EIP-712 `VMAction` type;
- the EIP-712 domain version changes from `"1"` to `"1.1"`;
- VM AccountId derivation uses only the verified explicit actor;
- recipient, router, executor and relayer remain separate signed roles;
- v1.0 action signatures are intentionally invalid under v1.1.

VM ISA v1, AccountId encoding, program packages, canonical SRC-20/SRC-721/SRC-1155 and CPAMM identities, and `VMReceipt` version 1 remain byte-for-byte unchanged.

## Security regression coverage

The suite locks the migration boundary with tests proving that:

- changing any signed action field cannot reclassify the action as a fresh nonce-zero actor;
- replacing the explicit actor while retaining a signature is rejected;
- a zero actor is rejected;
- a v1.0 domain/type signature is rejected by v1.1;
- a permissionless relayer does not become the VM actor;
- an actor may deliberately authorize a different recipient without transferring authority to it;
- every rejection rolls back the swap, nonce, execution height, VM state, Gas Token supply and aggregate `VMLog`.

## Compatibility and rollout

This is a hard wire-format boundary for authenticated actions. Wallets, routers and SDKs must encode the v1.1 envelope and sign the exact v1.1 domain/type. Existing v1.0 signatures must not be migrated or replayed; users sign a fresh v1.1 action instead. Unsigned NOP buys retain their existing behavior.

The frozen source of truth is `docs/spec/SwapVM-v1.1-frozen-spec.md`, authenticated by `docs/spec/SwapVM-v1.1-freeze-manifest.json`. The historical v1.0 specification and manifest are preserved unchanged.

## Verification checkpoint

Local verification with Foundry `1.5.1-stable`, Solidity `0.8.26`, Cancun semantics, IR compilation and optimizer runs `200` completed successfully:

- `forge fmt --check`, `forge build --sizes`, `forge test -vvv`, `forge snapshot` and `forge snapshot --check` passed;
- 72 tests passed with no failures or skips;
- the suite includes 512-case fuzz properties and eight stateful invariants running 64 runs x 32 calls;
- production runtime sizes are 21,918 bytes for `SwaputerKernel`, 5,842 bytes for `SwaputerHook`, 1,350 bytes for `SwaputerToken`, and 1,606 bytes for `SwaputerProgramRegistry`;
- the Kernel remains 2,658 bytes below the EIP-170 runtime-code limit.

This checkpoint is implementation evidence, not an external audit. Public deployment remains blocked on Stage 6 tooling and independent security review.
